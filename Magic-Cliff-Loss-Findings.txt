MAGIC CLIFF LOSS — REUSABLE FIRMWARE PORTING FINDINGS
Recorded 2026-10-28. Source: Generation Loss MKII firmware 1.1.0.
Status: experimental ARM insert effect, no physical pedal or Force/MPC test.

Use this as a method for another Chase Bliss project, NOT as a universal map.
A shared manufacturer does not establish a shared processor, sample rate,
control protocol, hardware front end, memory layout, or licensing terms.

1. IDENTIFY BEFORE EXECUTING
Input genLoss1.1.0.bin: 88,272 bytes.
SHA256 f9bfb4bfb28c551c1390a6ff1fc5c26873f5e3381ace65b7b363bd22e86cba67.
ARM Cortex-M image. Initial stack 0x20020000; reset 0x08006a3c.
Image base 0x08000000. Initialized data file range 0x10658..0x158d0,
length 0x5278, copied to 0x24000000. BSS extends to 0x24032f50.
Delay memory at 0x30000000. These addresses are specific to this image.
Hash-gate the loader; never apply offsets to an unverified different version.

2. ISOLATE THE AUDIO CORE
Initializer 0x080005d0 clears delays; 0x080006c8 takes s0=60 to prepare
input gain/saturation tables; 0x08000848 prepares floating-point noise data.
0x08005db8(r0=0): 16 interleaved stereo signed-int32 frames, 32 kHz.
Input 0x2400a0d4, output 0x24009ee8; normalization is 2^-31.
0x08002520 updates controls in three phases; packet at 0x2400a3d0.
Working init plus a valid packet matters: an uninitialized call can output
silence and does not prove the processor or image is unsupported.
Avoid running the full device boot sequence against a desktop host.

3. ARM INSTRUCTION ADAPTATION
Three unsupported conditional VFP select instructions require trampolines:
file 0x100fe: VSELEQ.F32 s15,s0,s15 -> IT EQ; VMOV s15,s0
file 0x10156: VSELGE.F32 s0,s0,s15 -> IT LT; VMOV s0,s15
file 0x10232: VSELGE.F32 s15,s15,s14 -> IT LT; VMOV s15,s14
Unselected register contents and condition flags are preserved.
Trampoline offsets 0x158d0,0x158da,0x158e4. Prepared size 88,302 bytes.
Patch GPIO function 0x08009e20 and device busy wait 0x08000954 to BX LR.
Do not remove arbitrary code on the assumption that it is hardware-only.
651 explicit relocations, including initialized pointer at file 0x1586c.
Discover relocations from reachable code/literal pools and switch tables;
blindly treating every pointer-like word as a pointer risks corrupting data.

4. PER-INSTANCE EXECUTION
Each instance gets separate code, working RAM and delay RAM. Relocate only
known words; initialized RAM must be copied AFTER code literal relocation.
Use writable memory to prepare code, clear instruction cache, then make RX.
Save/restore FPSCR around original code to avoid changing the host FP state.
No allocations, file reads or logging inside the audio callback.
Original mono/stereo/classic modes are retained in the firmware core.
Mode variable 0x24004e12: 0 classic MISO, 1 MKII MISO,
2 classic stereo, 3 MKII stereo. Initial interpretation was corrected using
saturation tables and model-selector behavior, not just nonzero audio.

5. CONTROL PACKET — ZERO-BASED BYTES
1..6: Wow, Volume, Model/LP, Flutter, Saturate/Generation, Failure/HP; 0..255.
7 bits 0..1 Aux mode index+1; bits 2..3 Dry index+1;
bits 4..5 Noise index+1; bit 6 high while Aux amount below midpoint.
8 active-low switches: bit6 Classic, bit5 MISO, bit4 Spread,
bit3 processed Dry, bit2 Drop Bypass, bit1 Snag Bypass, bit0 Hum Bypass.
9 Aux position: 127 idle, 0 fully engaged.
10 Hiss level; 11 Mechanical noise; 12 Crinkle; all 0..255.
13 Input gain index 0..2.
MKII model index at 0x240052a5 is clamped to 12; Classic routes the knob
into its filter behavior instead. Do not reuse parameter meaning by label
alone when a mode changes the algorithm.

6. AUX RESEARCH — PROTOTYPE REMOVED FROM FINAL EFFECT
The image receives an Aux envelope position from a separate controller.
The original pedal's onset/release timing is not established by this image.
FINAL DECISION: user chose a sound-controls-only insert. Tape Stop, Aux
Trigger, Tap Enable, timing and manual Aux were removed before publication.
Final packet fixes Aux idle (byte9=127,mode1,bit6 high). Findings below record
the earlier research, not features present in the delivered plugin.
The earlier prototype supplied a NEW linear host envelope, 0.05..5 seconds per full
transition. Its target is Aux Trigger AND Tap Enable. Manual Aux Amount is
independent; max(manual amount, envelope) is sent to the original DSP.
The firmware supplies the slowdown/filter/failure processing itself.
On-screen trigger latches; second tap releases. Turn off Tap Enable to
recover. Dry=None is needed for a full audible stop of the complete insert.
This is a live audio effect, not transport control or a loaded-record player.
Host bypass is latency-aligned and separate; DSP continues while bypassed.

Physical Q-Link TOUCH-ONLY activation is NOT implemented/verified.
The skin supports a touchscreen toggle and parameter mapping for knob
rotation. Neither proves that capacitive touch reaches setParameter.
Host Q-Link momentary macros reset on release, but documentation describes
movement as the trigger. Never identify touch from value deltas or assume
Enter Pressed means a physical Q-Link tap. A real host input trace is needed
before implementing or claiming touch-only support. Keep this open for next
hardware test; do not intercept global device input from an insert plugin.

7. SAMPLE RATE AND ANALOG BOUNDARY
The digital engine runs at 32 kHz. Host adapter uses 48-tap,1024-phase sinc
conversion and fixed 16-frame batching. Reported conversion/buffering delay:
82 samples at32k,104 at44.1k,110 at48k,194 at96k.
Pedal analog dry path is absent from the firmware DSP. Earlier research
inferred a 1dB/87-step attenuator mapping from RAM 0x32f10/0xa1e8, resembling
the M62429 protocol; actual circuit response was never measured.
FINAL INSERT: user requested a continuous Mix control. Firmware Dry=None
and clean-Dry-type are fixed, so there is no parallel firmware dry signal.
Host adds a latency-aligned original signal with linear coefficients
(1-Mix),Mix. Mix defaults to0.4 in every preset and is smoothed over a full
range of10ms. The inferred analog attenuation is NOT used in this version.
ADC/DAC, analog filters, headroom, exact unity gain and hardware-modified
pedals are not reproduced or proven by digital-core equality.

8. EVIDENCE
Original Unicorn MAX vs relocated/patched Cortex-A15: exactly identical
8192-frame stereo outputs in each of four routing modes. Native ARM code
under QEMU also matched those fixtures exactly. These are bounded tests,
not an exhaustive proof for every setting or the complete pedal.
VST host test: stereo effect category,18 automatable parameters,independent
instances,state chunks,NaN rejection,variable blocks1..1024 and four sample
rates,finite bounded output,latency-aligned host bypass.
Final performance test: ten factory presets produce finite stereo audio.
Earlier prototype also passed disabled-trigger,50ms/5s envelope and recovery
tests, but those controls are not part of the final effect.
No Force/MPC CPU benchmark or real-time underrun result. No hardware control,
automation-recording,discovery,preset-browser or save/reload validation.
Presets were designed from controls and signal-tested, not pedal-matched.

9. NEXT PEDAL WORKFLOW

11. PRESET DELIVERY
Ten built-in VST programs plus native MPC XPL presets. XPL effect metadata
uses MgGL UID, stereo inputs/outputs and isInstrument=0. JUCE base64 wraps
a VST2 FBCh bank chunk. Internal little-endian chunk v3 stores magic,version,
parameter count,program index,18 normalized floats,and a24-byte program name.
Installer replaces %payload-path% in Presets/*.xpl. Validate containers AND
load decoded chunks into the actual compiled library; do not call loose FXP
files native MPC presets. Edited state/name restoration is separately tested.
